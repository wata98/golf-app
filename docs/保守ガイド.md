# 保守ガイド

このアプリを自分で直したり変えたりするときの手引きです。
**直したら必ず `run-tests.bat` でテストを通し、版の番号を上げてから公開してください**（手順は README.md）。

---

## 1. フォルダとファイルの地図

```
golf-app/
├─ index.html            入口（4つのタブ・安全のための決まり CSP）
├─ manifest.webmanifest  ホーム画面に追加するための情報
├─ sw.js                 オフラインで開く仕組み（版の番号・保存するファイルの一覧）
├─ css/style.css         見た目（色・ボタンの大きさ）
├─ icons/                ホーム画面のアイコン（tools/make_icons.py で作り直せる）
├─ js/
│  ├─ app.js             起動したときの処理・タブを開いたときの処理
│  ├─ version.js         版の番号（sw.js と同じにする）
│  ├─ core/dates.js      日付の計算（バックアップのお知らせの30日）
│  ├─ db/                保存の仕組み（下の表）
│  ├─ ui/                タブ・お知らせ・確認の画面・グラフの読み込み
│  └─ features/          機能ごと（下の表）
├─ vendor/               同梱ライブラリ（書き換えない。版と指紋は vendor/README.md）
├─ tests/                自動テスト（*.test.js）
├─ tools/make_icons.py   アイコンを作るスクリプト
├─ docs/                 説明書
├─ start-local.bat       パソコンで開く
└─ run-tests.bat         テストを動かす
```

### 機能とファイル
| 機能（画面） | フォルダ | 主なファイル |
|---|---|---|
| ラウンドの記録（ラウンド中タブ） | `js/features/round/` | `hole-view.js` ホール入力 / `start-view.js` 開始 / `round-tab.js` 切り替え / `round-stats.js` 集計の計算 / `round-model.js` ラウンドの作り方 / `course-edit-view.js` パー・距離の編集 |

| マイクラブ（設定） | `js/features/clubs/` | `club-model.js` 最初の14本 / `clubs-settings-view.js` |
| 飛距離・番手早見表 | `js/features/distance/` | `distance-entry-view.js` 記録 / `distance-review-view.js` 集計とグラフ / `distance-stats.js` 計算 / `finder-dialog.js`・`club-finder.js` 早見表 |
| 弱点分析 | `js/features/analysis/` | **`analysis-rules.js` 判定のルール** / `analysis-metrics.js` 指標 / `analysis-view.js` 画面 |
| 練習メニュー・ドリル集 | `js/features/practice/` | **`practice-rules.js` メニューの作り方** / **`drill-data.js` 最初のドリル集** / `practice-menu-view.js` / `practice-record-view.js` / `drill-list-view.js` |

### 保存の仕組み（`js/db/`）
| ファイル | 役目 |
|---|---|
| `schema.js` | データの版（`SCHEMA_VERSION`）と棚の一覧 |
| `migrations.js` | 古い形のデータを新しい形に直す処理（版ごとに1つずつ） |
| `database.js` | スマホの中の保存場所（IndexedDB）の読み書き |
| `backup-format.js` | バックアップのJSONの作り方・確かめ方（楽天のキーを除く） |
| `image-codec.js` | スイングの静止画をJSONに入れるための変換 |

データの形のくわしい説明は `docs/data-model.md`。

## 2. 自分で変えたくなりそうな場所と変え方

変えたら、同じ名前の `tests/〜.test.js` も合わせて直し、`run-tests.bat` で通してください。
テストが通らないときは、テストの方の数字（期待する値）も新しいルールに合わせて直します。

| 変えたいこと | ファイル | 変える所 |
|---|---|---|
| 目標スコア | アプリの「設定」→「目標スコア」 | （画面で変えられる） |
| 弱点の判定の目安（目標スコアごとの失点の目安） | `js/features/analysis/analysis-rules.js` | `ALLOWANCE_TABLE` の数字（各行の合計が「目標−72」になるように） |
| バンカー1回を何打と数えるか | 同上 | `BUNKER_STROKES`（今は0.5） |
| 「参考値です」と出すラウンド数 | 同上 | `MIN_ROUNDS`（今は3） |
| 練習ドリルの中身 | アプリの「ラウンド前」→「ドリル集」 | （画面で追加・編集・削除できる） |
| 「最初のドリル集に戻す」で戻る中身 | `js/features/practice/drill-data.js` | `DEFAULT_DRILLS` の各ドリル |
| 練習メニューの配分（60・20・20） | アプリの「設定」→「練習メニューの配分」 | （画面で変えられる。初期値は `practice-rules.js` の `DEFAULT_SHARES`） |
| 弱点の項目と練習の課題の対応 | `js/features/practice/practice-rules.js` | `CATEGORY_TO_TOPICS` |
| 手応えと選ばれやすさ | 同上 | `drillWeight()`（今は「6 − 手応えの平均」） |
| 練習の球数・時間の選択肢 | `js/features/practice/practice-menu-view.js` | `AMOUNTS` |
| 攻略の基準（OB・池10%、バンカー30%） | `js/features/course/course-rules.js` | `LIMIT_OB_WATER` / `LIMIT_BUNKER` |
| 左右のブレを反映する条件 | 同上 | `BIAS_MIN_HOLES`（10ホール） / `BIAS_MIN_DIFF`（10ポイント） / `DEFAULT_SIDE_RATE`（15%） |
| 高低差の補正（1mにつき1ヤード） | アプリの「設定」→「番手早見表の高低差の補正」 | （画面で変えられる） |
| 最初の14本のクラブ | `js/features/clubs/club-model.js` | `DEFAULT_CLUBS`（すでに入っているクラブは「設定」→「マイクラブ」で直す） |
| スイングの場面の決め方 | `js/features/swing/swing-rules.js` | 先頭の `HIGH_ABOVE_ADDRESS` / `STILL_SPEED` など |
| スイングの cm の目安の比 | 同上 | `SHOULDER_WIDTH_RATIO`（0.23） / `TORSO_RATIO`（0.30） |
| バックアップのお知らせの日数（30日） | `js/core/dates.js` | `BACKUP_REMINDER_DAYS` |
| 色・文字の大きさ | `css/style.css` | 先頭の `:root` の色（`--main` など）と各部品の `font-size` |
| 空き確認の都県・時間帯の選択肢 | `js/features/availability/site-links.js` | `PREFS` / `TIME_ZONES` |

**データの形（保存する項目）を変えるとき**は、必ず `js/db/migrations.js` に移行処理を足し、`schema.js` の `SCHEMA_VERSION` を1つ上げ、`docs/data-model.md` に書き、移行のテストを足します（そうしないと保存済みのデータが読めなくなります）。

## 3. 壊れやすい場所と直し方

| 壊れる原因 | 症状 | 直し方 |
|---|---|---|
| **楽天GORA APIの仕様変更**（住所・版・キーの方式） | 空き確認で「接続先が見つかりません（404）」「返事の形が変わったようです」「楽天に断られました」 | `docs/availability-troubleshooting.md` の手順。直すのは `js/features/availability/gora-api.js` の `API_URL` と `parseResponse`。キーの方式が変わったら楽天ウェブサービスのお知らせを見る |
| **楽天のアプリの再登録・キーの期限** | 「楽天に断られました」が急に出る | 楽天からのメールを確かめ、楽天ウェブサービスでキーを確認し、「設定」に貼り直す |
| **予約サイトのデザイン・URLの変更**（楽天GORA・GDO） | 「〇〇の1人予約で開く」で開くが、日付やエリアが効いていない | `js/features/availability/site-links.js` だけを直す。手順は `docs/availability-troubleshooting.md` の「F」 |
| **国土地理院の地図の変更・停止** | 「地図で登録」で地図の写真が出ない | `js/features/course/green-map-view.js` の `TILE_URL`。国土地理院の「地理院タイル一覧」で新しいURLを確かめる。地図は登録のときだけ使うので、ラウンド中のGPSの距離は影響を受けない |
| **iOS の更新（Safari の変更）** | 画面が崩れる・ボタンが反応しない・動画が選べない・GPSが出ない | まず Safari の「設定」で JavaScript がオンかを確かめる。直らなければ、何の操作で何が起きたかをメモし、`docs/AIに相談するとき.md` の説明文と一緒に相談する |
| **iOS の更新でデータの保存の決まりが変わる** | データが消える | バックアップから復元する（だから月1回のバックアップが大事） |
| **MediaPipe が新しい iOS で動かない** | スイング解析で「骨格推定の部品を読み込めませんでした」 | `vendor/mediapipe/` を新しい版に入れ替える（`vendor/README.md` の手順。指紋の表と `sw.js` の `MEDIAPIPE_CACHE` の名前も変える） |
| **GitHub Pages の変更** | 公開サイトが開かない | GitHub のリポジトリの Settings → Pages で「Deploy from a branch」・`main`・`/(root)` になっているか確かめる |
| **版の番号の上げ忘れ** | 直したのに iPhone で古いまま | `js/version.js` と `sw.js` の `APP_VERSION` を上げて、もう一度公開する |
| **ファイルを足したのに `sw.js` に書き忘れ** | テスト「APP_FILES に足してください」が通らない／圏外で開けない | `sw.js` の `APP_FILES` にファイルを足す |
| **外部のサービスを足したのに CSP に書き忘れ** | 新しい通信や画像が出ない（ブラウザのコンソールに「Content Security Policy」） | `index.html` の CSP（`connect-src` や `img-src`）に住所を足す |

## 4. よくあるエラーと対処法

| 出る文章・症状 | 意味 | 対処 |
|---|---|---|
| 「データを開けませんでした。アプリを開き直してください」 | スマホの中の保存場所が開けない | アプリを完全に閉じて開き直す。続くときは iPhone を再起動。それでもだめならバックアップから復元 |
| 「このアプリのバックアップではありません」「ファイルを読めませんでした」 | 違うファイルを選んだ | `golf-backup-日付.json` を選ぶ |
| 「このデータは新しい版のアプリで作られています」 | 古いアプリで新しいバックアップを読んだ | アプリを最新にしてから読み込む（閉じて開き直す） |
| 黄色い「バックアップを保存してください」 | 30日以上バックアップしていない | 「設定」→「バックアップを保存」 |
| 「ファイルの準備ができました。もう一度…」 | 準備に時間がかかり、iPhone が共有画面を出さなかった | もう一度「バックアップを保存」を押す |
| 空き確認「楽天に断られました」 | キーか許可するWebサイトの間違い | README.md の「楽天GORAの空き確認を使う準備」をやり直す |
| 空き確認「メンテナンス中か混み合っています」 | 楽天側の都合、またはパソコンで開いている | 時間をおく。公開サイト（wata98.github.io）から開く |
| 空き確認「問い合わせが多すぎます」 | 短い時間に何度も検索した | 1分ほど待つ |
| スイング「動画が長すぎます」 | 10秒を超えている | 写真アプリの「編集」で前後を切る |
| スイング「体を十分に見つけられませんでした」 | 全身が写っていない・暗い | 撮り方の説明どおりに撮り直す |
| スイング「スイングを見つけられませんでした」「場面の順番がおかしく…」 | 自動で場面を決められなかった | 「直す」で1コマずつ動かして場面を決める |
| スイングの数値が「測れず」 | その場面で体の点がよく見えなかった | 撮り方を見直す（正常な動き。ほかの数値は使える） |
| グリーンまでの距離が出ない | グリーンを登録していない／位置情報を許可していない | 攻略プランで「地図で登録」。iPhone の「設定」→ プライバシー → 位置情報 → Safari（Webサイト）を許可 |
| 直したのに iPhone で変わらない | 古い版が残っている | 版の番号を上げて公開したか確かめ、アプリを完全に閉じて開き直す |
| `run-tests.bat` で ✖ が出る | 直したところと、テストの期待が合わない | ✖ の行のテスト名を見る。ルールを変えたならテストの数字も直す。違うなら直し方を見直す |
| `git push` で「rejected」 | GitHub の方が新しい | 別の場所で直した覚えがなければ、`git pull` してからもう一度 `git push` |
