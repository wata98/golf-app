## 1. 楽天GORAプラン検索API

### 2026年の仕様変更（重要）
- 2026年2月に楽天ウェブサービスのAPIが刷新され、**アプリIDに加えて「アクセスキー（accessKey）」が必須**になった。旧方式は2026年5月中旬で終了したとする記事が複数ある。
- 公式の新しいドキュメント（市場商品検索API・2026-06-15保存版）の記載:
  > Access key【NEW】 accessKey … Can be provided in either header or as query parameter
  > App ID applicationId … Required along with access key
- 接続先は `app.rakuten.co.jp` から `openapi.rakuten.co.jp` に変わった。
  GORAプラン検索の新しい接続先は、応答を確かめて **`https://openapi.rakuten.co.jp/engine/api/Gora/GoraPlanSearch/20170623`** と判断した（ほかの候補は「404 見つからない」、これだけが「400 パラメーター不足」を返した）。
- 技術記事によると、アプリの設定に「許可するWebサイトURL」を登録し、**Referer（どのページから呼んだか）がそれと合わないと拒否**される（`HTTP_REFERRER_MISSING` / `HTTP_REFERRER_NOT_ALLOWED`）。ブラウザから呼ぶ場合、Referer はブラウザが自動で付ける。

### スマホのブラウザの中のPWAから直接呼べるか → **呼べる見込みが高い**
アクセスキーなしで新しい接続先に問い合わせた結果:

| 確かめたこと | 結果 |
|---|---|
| 公開サイト（`https://wata98.github.io`）から呼んだときの応答に「どのサイトからでも読んでよい」という印があるか | ある（`Access-Control-Allow-Origin: *`） |
| アクセスキーをヘッダーで送るときの事前確認（プリフライト）に応じるか | 応じる（`access-control-allow-headers: accesskey`、`access-control-allow-methods: GET`） |
| Referer なしで呼んだとき | 拒否（403） |

→ ブラウザ（PWA）からの直接の呼び出しは、仕組みの上では許されている。サーバーは不要。
ただし、本物のキーで Referer の照合（`https://wata98.github.io/` で通るか）をまだ確かめていない。

### アプリID・アクセスキーを公開してよいか → **公開してはいけない**
楽天ウェブサービス利用規約 第5条（App ID）第2項（日本語の原文がサイト不調で読めず、公式の英語訳から引用。英語訳は参考で、日本語の原文が優先と書かれている）:
> 2. The Developer must store the app IDs responsibly, without allowing any other person to gain knowledge of it.

（訳: デベロッパーは、アプリIDを他人に知られないよう、責任をもって保管しなければならない）

- リポジトリは公開なので、**コードやファイルに書いてはいけない**（最初に決めたとおり、設定画面で入力してスマホの中だけに保存する）。
- スマホから楽天への通信は暗号化（https）されるので、見えるのは本人だけ。これは「他人に知られる」には当たらないと考える。
- **バックアップのJSONには入れない**ことを提案する（バックアップのファイルを人に渡したり置き忘れたりしても漏れないように。機種変更のときは入れ直す）。

### 無料か
- 利用規約 第7条第2項（英語訳）:
  > 2. The Developer must pay the usage fees, which relate to the permission raised in the previous clause, if the Company decides this separately.
- 今は利用料の定めは見つからず、無料で使われている（複数の記事も「誰でも無料で使用できる」と説明）。**ただし、将来有料にできる条文がある**。有料になったら使うのをやめる（リンク集だけに戻す）。

### 利用制限
- 公式ドキュメント（2025年保存版）:
  > ※短い時間の間に大量に、同一のリクエストURLへアクセスすると、一定時間利用できなくなる場合がございます。
- 回数の上限は、読めたページには数字で書かれていなかった。超えると `429 too_many_requests`。
- 利用規約 第7条第3項で、楽天はアクセス回数などを制限できる。
- → **1秒に1回以下**に抑え、1回の検索で取りに行くページ数も絞る。

### 指定できる条件（公式ドキュメント 2017-06-23版、2025年保存版より）
| 依頼の条件 | APIで指定できるか |
|---|---|
| 日程 | `playDate`（1日だけ。YYYY-MM-DD）。複数の日を見るには日ごとに呼ぶ |
| 人数（1〜4人） | **入力では指定できない**。結果の `playerNumMin`（最小プレー人数）/`playerNumMax` で、アプリの中で絞り込む |
| エリア（都県） | `areaCode`（複数可。例 `8,9,10,11,12,13,14` で関東）。ゴルフ場名・ゴルフ場IDでも可（どれか1つは必須） |
| 予算 | `minPrice` / `maxPrice`（最大価格は25,000円まで） |
| スタート時間帯 | `startTimeZone`（4〜15時台、複数可） |
| その他 | 並び順 `sort`（料金が安い順など）、昼食付・2サム保証などのプランの条件、1ページ30件まで・100ページまで |
| 1人予約 | **指定できるパラメーターがない** |

### 返ってくる情報（主なもの）
- ゴルフ場: 名前、都道府県、最寄りIC、評価、予約カレンダーのURL
- プラン: プラン名、料金（総額・税抜き・税）、最小・最大プレー人数、スタート時間帯、ラウンド数、キャディ有無、カート、**2サム保証**、2B・3B追加料金、昼食
- 空き: プレー日、在庫ステータス（1: 空き有り/リクエスト予約可 … 6: キャンセル待ち）、在庫数、**予約ページのURL（スマホ用もある）**
- **1人予約の情報（予約が成立しそうか、今何人集まっているか）は出力にない**

### 表示の決まり
- 利用規約 第13条: 楽天が求める場合、情報が楽天提供であることを決められた形で表示する。→ 実装時に、楽天の決まった表示（クレジット）を検索結果の下に入れる。

## 3. 自動取得（プログラムで画面を読むこと）と利用規約

### 楽天GORA
**楽天GORA利用規約（2026年5月15日改定）**には、プログラムによる取得を名指しで禁止する条文はない。ただし次の条文がある:
> 第１条３．利用者は、本規約の他、本規約の下位規約、各種ガイドライン等を遵守するとともに、楽天会員規約を遵守するものとします

> 第１３条３．利用者は、楽天GORAを私的な目的にのみ利用することができます。

> 第１４条３．利用者は法律で認められた私的利用の範囲を超えて、GORAコンテンツにつき、複製、転載、頒布、翻訳、その他一切の利用をする事はできません。

その「楽天会員規約」（最終改定日2025年12月19日）の第８条（禁止事項）:
> 会員サービスが通常意図しないバグを利用する動作、その他通常意図しない効果を及ぼす外部ツールの利用・作成・頒布を行う行為

> 会員サービスまたは楽天のサーバーに過度の負担をかける行為

- robots.txt（検索ロボット向けの決まり）では、1人予約の検索ページは禁止されていない。
- **判断**: 「通常意図しない効果を及ぼす外部ツールの利用・作成」に、画面を自動で読むスクリプトが当たると楽天が判断する余地が大きい。違反と判断されると楽天会員の資格を取り消される可能性があり（第９条）、楽天のほかのサービスにも影響する。**「規約上問題がない」とは言えない**。

### GDO
**GDO総合利用規約（2009年11月24日制定）**には、プログラムによる取得を名指しで禁止する条文はない。ただし:
> 第7条（私的利用の制限および営利目的利用の禁止）本サイトは、利用者が私的かつ非営利目的で使用するために提供するものです。

禁止事項の「その他」:
> (8) その他、当グループが合理的な理由にもとづき不適切と判断する行為

- スクリプトから robots.txt を読もうとしただけで **403（拒否）** が返った。プログラムからのアクセスを技術的に止めている。
- **判断**: 名指しの禁止はないが、運営側がプログラムからのアクセスを止めており、それをくぐり抜けて読むのは「不適切と判断する行為」に当たる可能性が高い。**問題がないとは言えない**。

### じゃらんゴルフ
**じゃらんゴルフ利用規約（2025年11月1日改定）** 第5条（ユーザーの遵守事項）第4項第2号で禁止:
> 当社の承認した以外の方法により本サービスを利用する行為

- **判断**: プログラムでの自動取得は承認された方法ではないので、**禁止に当たる**。

### まとめ
3サイトとも自動取得を認めておらず、少なくとも1つ（じゃらんゴルフ）は明確に禁止、ほかの2つも規約違反と判断される余地が大きい。**依頼の条件「規約上問題がない場合だけ」を満たさないので、1人予約の自動取得（Playwright のスクリプト）は作らないことを提案する。**

## 4. 提案する作り方（承認待ち）

### 通常の空き検索 → アプリから楽天GORAプラン検索APIを直接呼ぶ
- 「ラウンド前」タブに「空き確認」を足す。条件: 日程（1日〜数日）、人数、エリア（関東の都県）、予算、スタート時間帯
- 人数はAPIで指定できないので、最小〜最大プレー人数で絞り込む
- 複数の日・都県はまとめて1回にできるもの（都県）はまとめ、日ごとの呼び出しは1秒以上あける
- 結果の各プランに「予約ページを開く」ボタン（楽天の予約ページへ。予約はそこで自分でする）
- 設定画面にアプリID・アクセスキーの入力欄（スマホの中だけに保存、バックアップに入れない）。楽天側には「許可するWebサイトURL」に `https://wata98.github.io/` を登録してもらう（手順は実装時に案内）
- 未入力のときは、リンク集（下の1人予約のボタンと、楽天GORA・GDOの通常検索を条件入りで開くボタン）だけを出す
- 直接呼べなかった場合の代わり: 条件入りで楽天GORAの通常検索ページを開くボタンだけにする（無料の中継サーバーも考えられるが、登録が増え、無料枠の扱いを確かめる必要があるので、まずはやらない）

### 1人予約 → 条件入りで各サイトの1人予約検索ページを開くボタン
条件をURLに入れて開けることを確かめた:
- 楽天GORA 1人予約: `https://search.gora.golf.rakuten.co.jp/?menu=srch_solo&act=disp&month=11&day=15&widthday=1&plan_day=-1&rates_min=0&rates_max=10000&area[]=12&zone_list[]=7`
  - エリア `area[]`（8茨城・9栃木・10群馬・11埼玉・12千葉・13東京・14神奈川）、時間帯 `zone_list[]`（6〜11）、予算 `rates_max`（決まった金額のみ）、日数 `widthday`（1〜8）
  - 「先に予約者がいるプラン」`is_appl_flg=1`、「満員を除外」`is_except_full_flg=1` もある（実装時に動きを確かめる）
  - 結果の画面に「開催見込」など予約の成立状況が出る
- GDO 1人予約: `https://oc.golfdigest.co.jp/search?s=1&dp=2026-11-15&during=1&pref[]=千葉県&start_time[]=7&price_upper=10000&unfull=1`
  - 千葉県・11/15・7時台で19件に絞り込まれることを確かめた
  - 「先行予約者あり」`check_already=1` もある
- じゃらんゴルフは、1人予約の検索ページの形を確かめていないので、今回は入れない（必要なら次に調べる）

### 動かなくなったときのエラー（実装時）
- 楽天APIの応答ごとに日本語で出す（例: 「アクセスキーが正しくありません」「許可するWebサイトURLの登録を確かめてください（Refererの不一致）」「回数が多すぎます。少し待ってから」「楽天のAPIの形が変わったようです（〇〇の項目がありません）」）
- エラーの形が2種類ある（`error`/`error_description` と `errors`/`errorCode`/`errorMessage`）と報告されているので、両方に対応する
- 1人予約のボタンは、サイトの検索URLの形が変わると条件が効かなくなる（エラーにはならない）。直し方を `docs/` に書く
